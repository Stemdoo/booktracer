# REST API BookTracer

Базовый адрес локально: `http://127.0.0.1:8000`. На Render используйте HTTPS-адрес своего Web Service. JSON-ответы формируются Django REST Framework.

## Публичные GET-маршруты

### `GET /api/books/`
Список книг, поиск, фильтрация, сортировка и пагинация. Авторизация не требуется.

Query-параметры:
- `search` — поиск по названию или имени автора.
- `genre` — ID жанра.
- `ordering` — `title`, `-title`, `author__name`, `-author__name`, `id`, `-id`; по умолчанию `-id`.
- `page` — номер страницы, размер страницы 10.

Успешный ответ:
```json
{
  "results": [
    {
      "id": 1,
      "title": "Название книги",
      "author_name": "Имя автора",
      "genre_name": "Жанр",
      "available_copies": 2
    }
  ],
  "count": 1,
  "total_pages": 1
}
```
Реальный ответ зависит от данных базы. Некорректный `page` может привести к ошибке преобразования, так как текущий view преобразует параметр через `int()` без отдельной обработки.

### `GET /api/books/<book_id>/`
Детальная информация о книге; авторизация не требуется.

Пример ответа:
```json
{
  "id": 1,
  "title": "Название книги",
  "description": "Описание",
  "snippet": "Фрагмент текста",
  "author_name": "Имя автора",
  "genre_name": "Жанр"
}
```
Если книга не найдена, возвращается HTTP 404 и `{"error": "Книга не найдена"}`.

### `GET /api/genres/`
Возвращает массив жанров вида `[{"id": 1, "name": "Фэнтези"}]`. Авторизация не требуется.

## Статусы чтения — требуется авторизация

Все записи ограничены текущим `request.user`. При отсутствии сессии DRF обычно возвращает HTTP 403 для SessionAuthentication или HTTP 401/403 в зависимости от настроенной схемы аутентификации.

### `GET /api/my-book-statuses/`
Возвращает список статусов чтения текущего пользователя.

### `POST /api/my-book-statuses/`
Создаёт запись. Тело JSON:
```json
{"book": 1, "status": "to_read"}
```
Поле `book` — существующий ID книги. Новая запись должна иметь `to_read`; повторная запись той же книги запрещена. Успех — HTTP 201.

### `GET /api/my-book-statuses/<status_id>/`
Получение собственной записи. Чужая или отсутствующая запись возвращает 404.

### `PATCH /api/my-book-statuses/<status_id>/`
Частичное изменение собственной записи. Например:
```json
{"status": "reading"}
```
Допустимы переходы `to_read` → `reading` → `read`. Недопустимые данные дают HTTP 400.

### `DELETE /api/my-book-statuses/<status_id>/`
Удаляет собственную запись. Успех — HTTP 204 без тела.

## Бронирования — требуется авторизация

### `GET /api/reservations/`
Возвращает бронирования текущего пользователя. Необязательные фильтры: `status` (`created`, `confirmed`, `issued`, `returned`, `cancelled`) и `genre` (числовой ID жанра). Некорректный статус или жанр — HTTP 400.

### `POST /api/reservations/`
Создаёт бронирование доступной книги:
```json
{"book": 1}
```
`user`, `status` и даты задаются сервером. Успех — HTTP 201; отсутствие доступных экземпляров, неверная книга или уже активное бронирование — HTTP 400. При создании записывается событие.

### `GET /api/reservations/<reservation_id>/`
Получает собственное бронирование; иначе HTTP 404.

### `PUT /api/reservations/<reservation_id>/` и `PATCH /api/reservations/<reservation_id>/`
Изменяют новое (`created`) бронирование, например `{"book": 2}`. Нельзя редактировать подтверждённое или более позднее бронирование. Успех — HTTP 200; ошибки проверки — HTTP 400.

### `DELETE /api/reservations/<reservation_id>/`
Удаляет только бронирование со статусом `created`. Перед удалением создаётся событие истории. Успех — HTTP 204; для других статусов — HTTP 400.

### `POST /api/reservations/<reservation_id>/action/`
Выполняет переход статуса. Тело:
```json
{"action": "confirm"}
```
Доступные действия:
- `confirm`: `created` → `confirmed`, уменьшает доступный остаток.
- `issue`: `confirmed` → `issued`.
- `return`: `issued` → `returned`, увеличивает доступный остаток.
- `cancel`: `created` или `confirmed` → `cancelled`; при отмене подтверждённого бронирования остаток увеличивается.

Успешный ответ содержит `message`, объект `reservation` и `available_copies`. Неизвестное действие, запрещённый переход или отсутствие экземпляров дают HTTP 400. Не принадлежащее пользователю бронирование возвращает 404.

### `GET /api/reservations/<reservation_id>/events/`
Возвращает события истории только для собственного бронирования. Требуется авторизация; чужой или отсутствующий объект — HTTP 404.

## HTML-маршруты, не являющиеся REST API

- `GET /` — каталог.
- `GET /dashboard/` — интерактивный каталог.
- `GET /books/<book_id>/` — страница книги.
- `GET /books/<book_id>/snippet/` — JSON-фрагмент книги.
- `POST /books/<book_id>/favorite/` — переключение избранного, требуется вход.
- `POST /books/<book_id>/status/` — обновление статуса через форму, требует вход и CSRF.
- `GET /my-books/` — личные книги, требует вход.
- `GET /reservations/` — страница бронирований, требует вход.
- `GET /accounts/login/` и другие стандартные `/accounts/` маршруты — встроенные страницы авторизации Django.
- `/admin/` — административная панель.

## Аутентификация и CSRF

Изменяющие запросы из браузера с сессионной авторизацией должны передавать CSRF-токен, когда включена `SessionAuthentication` и проверка CSRF. Не размещайте реальные пароли, cookie или CSRF-токены в документации. Для проверки в браузере используйте DevTools → Network и проверяйте HTTP-статус и JSON-ответ.
