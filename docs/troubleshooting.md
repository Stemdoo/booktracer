# Типичные ошибки и диагностика

## 1. `DisallowedHost` или HTTP 400
**Причина:** домен запроса отсутствует в `DJANGO_ALLOWED_HOSTS`. Для ошибок CSRF проверьте `DJANGO_CSRF_TRUSTED_ORIGINS` и схему `https://`.

**Проверка:** посмотрите лог Render и точный hostname в адресной строке. Добавьте только фактический домен сервиса, затем перезапустите/передеплойте сервис.

## 2. HTTP 500 и `relation ... does not exist`
**Причина:** миграции не выполнены в той базе, к которой подключён Web Service, либо приложение подключено не к ожидаемой базе.

**Проверка:** проверьте `DATABASE_URL` в Render без копирования значения в переписку; выполните `python manage.py showmigrations` и `python manage.py migrate` в среде с теми же переменными, что у Web Service.

## 3. Каталог пустой, хотя локально книги есть
**Причина:** локальная SQLite и PostgreSQL Render — разные базы; миграции не копируют записи.

**Проверка:** откройте `/api/books/`. Если `count` равен 0, проверьте наличие книг в админке именно публичного сайта. Затем выполните контролируемую загрузку fixture или импорт данных в нужную базу.

## 4. `ModuleNotFoundError` при сборке
**Причина:** пакет отсутствует в `requirements.txt` или установлена неподходящая версия Python/зависимости.

**Проверка:** найдите первый traceback в Build Logs, сравните используемую версию Python и `requirements.txt`, затем установите пакет в файл зависимостей и повторите сборку.

## 5. REST API возвращает 401/403
**Причина:** endpoint требует авторизации, отсутствует действующая сессия либо изменяющий запрос не прошёл CSRF-проверку.

**Проверка:** сначала войдите в систему; в DevTools → Network проверьте cookies, заголовок CSRF и статус ответа. Не публикуйте cookie и токены.

## 6. REST API возвращает 400
**Причина:** неверный ID книги/жанра, недопустимый статус, нет доступных экземпляров или переход бронирования не разрешён.

**Проверка:** изучите JSON тела ответа; проверьте допустимые значения в `docs/api.md` и фактическое состояние объекта.

## 7. CSS/JavaScript не загружаются на Render
**Причина:** статические файлы не собраны или URL ресурса неверный.

**Проверка:** выполните `python manage.py collectstatic --noinput`, убедитесь, что `STATIC_ROOT` задан, откройте DevTools → Network и проверьте ошибки 404. Сборка `build.sh` выполняет `collectstatic`.

## 8. Изменения исчезают после перезапуска
**Причина:** приложение использует SQLite в файловой системе сервиса или подключено к другой/временной базе.

**Проверка:** на Render проверьте, что `DATABASE_URL` задан и приложение подключается к PostgreSQL. Создайте тестовую запись, перечитайте её после перезапуска. Не используйте локальную SQLite как постоянное хранилище публичного сервиса.
